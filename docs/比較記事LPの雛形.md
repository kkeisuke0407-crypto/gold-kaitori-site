# 比較記事型LPの雛形（N社比較 → 2社推薦）

`/manekiya-otakaraya/` を分解して雛形化したもの。**どの案件でも同じ形で作れる**ようにしてある。

| | |
|---|---|
| **ひな形** | `templates/hikaku-lp/index.html` + `style.css` |
| **生成** | `npm run new-hikaku -- scripts/hikaku-configs/<slug>.config.mjs` |
| **config例** | `scripts/hikaku-configs/_example.config.mjs` |
| **完成見本** | `public/manekiya-otakaraya/`（このドキュメントの行番号は全部このファイル） |
| **生成先** | `public/<slug>/`（Astroが `public/` をそのまま公開する） |

> LP3 / LP2nd（`docs/新しいLPの作り方.md`）とは**別ジャンル**。
> あちらは「1社訴求の縦長LP（Astro）」、こちらは「N社比較して2社に絞る読み物（素のHTML）」。
> 検索意図が「◯◯ vs ◯◯」「おすすめ比較」「どこがいい」なら**こちら**を使う。

## 1. この型が何をやっているのか（設計思想）

売り込みではなく、**読者の判断を1本の線に載せ替える**構成になっている。

```
読者の状態： どこも「業界最高値」で、違いが分からない
      ↓ ①結論を先に出す           → 探す作業を終わらせる
      ↓ ②ランキング・検索順位を無効化 → 既存の判断軸を壊す
      ↓ ③「最終手取り」を唯一の軸に置く → 新しい判断軸を渡す
      ↓ ④N社を並べて調べた量を見せる  → 軸で比べた事実を出す
      ↓ ⑤査定額の計算式を見せる      → 単価比較が無意味だと分かる
      ↓ ⑥「はい/いいえ」1問に落とす   → 自分の答えが確定する
      ↓ ⑦不安を1つずつ消す          → 行動のコストを下げる
到達点： 「エリア内なら主推薦社／それ以外なら副推薦社」を自分で選んだ気になる
```

**この型の効きどころは3つ。ここを外すと、ただのアフィリ記事に落ちる。**

1. **順位を付けない**（1位/イチオシ/ランキング禁止）。「ランキングは信用できない」と本文で言っておいて自分が順位を付けたら、記事全体の信頼が消える。代わりに**役割の違い**（手取り重視／近くで査定）で2社を分ける。
2. **弱みを本物で書く**。`弱み｜正直に3つ書きます` と `利用前に確認したいこと` は飾ると全部崩れる。ここが信頼の担保。
3. **推薦の根拠を「エリア」に置く**。主観の優劣ではなく、読者の住所という**動かせない事実**で分岐させるので反論が起きない。副推薦社は「主推薦が使えない人の受け皿」であって、格下ではない。

## 3. 4つの機構

### 3-1. CV計測

主CVは**アフィリ先への送客クリック**（詳細は `docs/cv-measurement.md`）。

| イベント | 意味 | 送信先 |
|---|---|---|
| `gold_kaitori_affiliate_click` | 主推薦社（成果） | GA4 + Google Ads |
| `gold_kaitori_other_click` | 副推薦社（非成果） | GA4 + Google Ads |
| `gold_kaitori_phone_click` / `_web_click` | 電話/WEB別の質 | GA4のみ（`send_to`） |
| `gold_kaitori_landing_intent` / `<intent>_open` | 到達 | GA4 |

判定は**href のホスト名**。`secondary.host`（例 `otakaraya.jp`）に一致すれば非成果、それ以外は成果。

> ⚠️ **CTAのclassを増やしたら、スクリプト内の `SEL` にも必ず足す。**
> 過去にクラス名を `kin-pv` → `kin-pv-banner` に変えて `SEL` を直し忘れ、
> FV直下のCTAが**まるごと計測漏れ**していた。雛形にはコメントで注意書きを入れてある。
> 追加したら §6 のチェックリストでクリック実測すること。

### 3-2. キャンペーン日付の自動計算

`#kin-camp-range` と `#kin-today` をJSTで毎日書き換える。`primary.campaign.type` で選ぶ。

- `monthly` … 当月1日〜末日（**まねきや**）
- `weekly` … 次の日曜まで（**おたからや**）

**この2つを取り違えないこと。** 比較表・カウントダウン両方に影響する。

### 3-3. 相場計算機

`/rates.json`（`src/pages/rates.json.js` → `src/data/rates.json`、田中貴金属ベースでGitHub Actionsが毎日更新）を fetch して `単価 × 重量` を出す。貴金属以外の商材では `calc: false`。

### 3-4. 強調の3色

| クラス | 用途 |
|---|---|
| `em-mark`（黄マーカー） | そのセクションの**結論・パンチライン**。最も目立つので1ブロック1〜2個まで |
| `em-green` | メリット・無料・得 |
| `em-red` | 注意・条件・危険信号 |

素の `<strong>`（金の細線）は通常の強調。使い分けないと全部同じ強さに見えてメリハリが消える。

## 4. 作り方（手順）

1. **画像を用意**して `public/<slug>/images/` に置く（FV・バナー2枚・ロゴ2枚・地図・店舗写真・キャンペーン画像）。
   FVに**文字を焼き込まない**。結論はHTML側で出す。
2. **config を作る**：`scripts/hikaku-configs/_example.config.mjs` をコピーして `<slug>.config.mjs`。
3. **生成**：
   ```bash
   npm run new-hikaku -- scripts/hikaku-configs/<slug>.config.mjs
   ```
   → `public/<slug>/index.html` と `style.css` ができる。未配置画像・`bad`口コミ無し等は警告で出る。
4. **`▼書き換え` を全部つぶす**。生成直後は雛形の骨が残っている。放置すると別商材の記述が混ざる。
5. `npm run build` → `npm run dev` で `/<slug>/` を目視確認。
6. §6 のチェックリストを通す。
7. ブランチにコミット → PR → マージで公開（デプロイ自動）。

**config の文字列は HTML として埋め込まれる**ので `<strong class="em-mark">` 等がそのまま使える。`alt` / `aria-label` に入る値だけは自動エスケープされる。

## 5. 文章の書き方

### 語り口調にする
- 「〜と考えられます」「〜な可能性があります」→ **禁止**。読者は判断を求めている。
- 体言止め・言い切り・口語をためらわない。「べつに今すぐ売らなくていいんです。」「金は逃げません。」
- 1文を短く。段落は2〜3文。改行は**語句の途中で切れない**ようにする（`word-break: auto-phrase` が効くが `<br>` の位置は手で見る）。

### 断定してよいこと／いけないこと

| 書ける | 書けない |
|---|---|
| 「公式に◯◯と記載がある」 | 「◯◯が最も高い」「業界No.1」 |
| 「レートを公開している」 | 「必ず高く売れる」 |
| 「確認できたのはこの2社だった」 | 「他社は安い」 |
| 「◯◯円の実績が掲載されている」（＋特定の取引例の注記） | 「◯◯円で売れます」 |

**攻めるのは表現、ゆるめるのは事実の断定ではない。** 「買い叩かれる確率がガクッと下がります」は書ける（読者の行動の効果）。「この店が一番高い」は書けない（優劣の断定＝景表法）。

### 事実確認は必ずやる
過去に「主推薦社=直営／他社=FC」という論を立てたが、**主推薦社自身がフランチャイザーだった**ため全面的に書き直した。
比較の軸にする事実は、必ず**両社の公式ページで裏を取る**。取れない軸は使わない。

## 7. 雛形を直したとき

- ひな形（`templates/hikaku-lp/`）を直しても、**既存ページには自動で反映されない**。
  全ページに効かせたい変更なら、各 `public/<slug>/` にも展開する。
- 逆に、実ページで見つけた良い改善は**ひな形に戻す**。戻さないと次の案件で消える。
- ひな形に新しい `{{TOKEN}}` を足したら、`scripts/new-hikaku.mjs` の `tokens` にも足す。
  足し忘れると生成時に「未置換のトークンが残っています」で止まる（安全側に倒してある）。

## 8. 雛形化のときに直した負債

完成見本には残っているが、雛形には持ち込んでいないもの。**実ページを触るときも直す方向で。**

1. **比較表の列3本が後付けJS**（見本 `index.html:203-292`）。`children[5]` のインデックス依存で、列を1本足すだけで壊れる。雛形はHTMLに直書き。
2. **死んだマークアップ**（見本 `index.html:294-312`）。`kin-cmp9-scale` テーブルが inline CSS で `display:none` のまま配信されている。雛形では削除。
3. **head のSEO欠落**（見本 `index.html:3-7`）。`description` / `canonical` / OG / FAQPage schema が無い。雛形では全部入れてある。
4. **inline `<style>` の散らばり**。雛形では `style.css` 末尾の「雛形で共通化した分」に集約し、生成ページは inline `<style>` を持たない。
